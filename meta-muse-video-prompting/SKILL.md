# Meta Muse Video 영상 프롬프트

## 범위와 근거

사용자가 영상 제작 문맥에서 ‘메타 Muse AI’라고 하면 Meta의 Muse Video용 프롬프트로 처리한다. Muse 개인 비서, Muse Spark의 텍스트/추론 기능, Muse Image의 이미지 기능, Realtime Avatar를 영상 생성 모델과 혼동하지 않는다. 동명의 제3자 사이트가 Meta 공식 서비스라고 가정하지 않는다.

확인일: 2026-11-02. [Meta의 Muse Image·Muse Video 소개](https://ai.meta.com/blog/introducing-muse-image-muse-video-msl/)에서 Muse Video와 native audio를 확인했다. 이 소개만으로 현재 모든 계정의 영상 접근 권한·모든 입력 모드·정확한 길이·요금·출력 해상도를 확정하지 않는다. Muse Image의 멀티 참조·편집·도구 사용 기능을 Muse Video의 지원 사양으로 전용하지 않는다.

[Meta Model API 개요](https://dev.meta.ai/docs/overview)에 영상 이해나 이미지 API가 있다는 사실은 영상 생성 엔드포인트의 근거가 아니다. 현재 공개 문서에서 Muse Video 스키마를 확인하기 전에는 모델 ID, /videos 경로, SDK 메서드, 키 이름을 발명하지 않는다.

## Claude·Codex 공용

Claude Code: `~/.claude/skills/meta-muse-video-prompting/`에 폴더 전체를 설치하고 `/meta-muse-video-prompting`으로 호출한다. Codex: `~/.codex/skills/meta-muse-video-prompting/`에 설치하고 `$meta-muse-video-prompting`으로 호출한다. Claude 사용자 스킬은 제공 ZIP을 업로드·활성화한 후 자연어로 요청한다. `agents/openai.yaml`은 Codex UI용이며 실행 의존성이 아니다.

도구 이름을 특정 호스트에 고정하지 않는다. 현재 환경에서 파일 읽기·이미지 확인·웹 검색·연결 도구를 사용한다. 영상 연결이 없어도 프롬프트 작성은 완료한다.

## Muse용 작성 결정

- 짧은 영상의 중심 사건을 먼저 정한다. 주체·시작 상태·읽히는 행동·관찰 가능한 반응·끝 상태가 하나의 흐름을 이루게 쓴다. 이는 로컬 연출 원칙이며 Meta가 지정한 공식 필수 양식이라고 하지 않는다.
- 이미지 기반 요청은 실제 첨부를 읽고 그 포즈와 공간에서 가능한 행동을 설계한다. ‘첫 프레임으로 사용’은 사용자의 의도이며 실제 UI의 시작 프레임 제어 지원과 구별한다. I2V나 참조 슬롯이 현재 계정에 없다면 있다고 약속하지 않는다.
- 인물이 움직여야 하는 장면은 손·고개·몸의 방향 변화와 그 결과를 명확히 쓴다. 카메라·나비·입자·바람만 움직이는 정적 인물 프롬프트로 대체하지 않는다. 먼 인물은 미세 표정 대신 팔의 움직임이나 몸의 기울기처럼 구도에서 읽히는 행동을 선택한다.
- 대사가 있으면 화자별 정확한 문구와 말투·쉼을 오디오에 따로 쓴다. ‘대사 없음’은 시각적 인물 행동을 금지하지 않는다. 립싱크·발화·시간 정밀도는 생성 목표이며 보장이 아니다.
- native audio를 고려해 NO BGM과 허용 현장음을 분명히 쓴다. 빛나는 꽃이나 나비에 자동으로 음악적 반짝임을 붙이지 않는다. 완전 무음·원본 오디오만·무반주 노래는 다른 모드로 처리한다.
- 길이와 화면비를 요청대로 설계하되 실제 생성 지원과 구별한다. 5초 요청을 임의로 10/15초로 바꾸거나 커뮤니티 예시의 길이를 공식 한도로 간주하지 않는다. 지원하지 않는 길이면 생성 길이와 편집 후 목표 길이를 나눠 설명한다.
- 타임코드, 카메라·조명·참조 고정은 연출 지시다. 별도 컨트롤·업로드·프레임 지정이 확인되지 않았으면 실행 가능한 숨은 파라미터로 설명하지 않는다.
- JSON 요청에는 유효한 제작 브리프 JSON으로 작성하고 ‘Meta 공식 API 요청 형식’과 구별한다. 사용자 스키마가 있으면 그 구조를 보존하고 필요한 행동·끝 상태·오디오를 담는다. 사용자 요청이 없으면 복사 가능한 일반 텍스트를 기본으로 한다.

## 작성 흐름

1. 입력이 주제·스토리·이미지·기존 프롬프트 중 무엇인지 정한다. 이미지는 실제로 확인한다. 이야기의 사건과 이미지의 외모·초기 자세를 구별한다.
2. [장면 연출](references/directing.md)을 읽고 인물 행동·카메라·조명·음향·끝 상태를 설계한다. 영화·판타지·광고·뮤직비디오에 맞는 지시만 선택한다. 씨댄스 2.5의 규칙을 각색한 로컬 작성법이며 해당 모델의 공식 문법이 아니다.
3. 최신 요청의 길이·화면비·언어·컷 정책·자료 역할·대사를 보존한다. 특정 장면의 5초·NO BGM을 모든 미래 영상의 기본값으로 확장하지 않는다. 누락은 맥락에서 추정하되 결과를 바꾸는 필수 정보만 질문한다.
4. 참조별 얼굴·의상·공간·스타일·동작·첫/끝 프레임 역할과 충돌 우선순위를 정한다. 실제 업로드 이름/태그만 쓴다. 가상의 @image 태그나 입력 슬롯을 만들지 않는다.
5. 주체의 행동을 카메라와 분리한다. 동작 요청에 카메라·바람·입자만 움직이게 쓰지 않는다. 초기 접촉 상태 → 행동/힘 → 물체 반응 → 인물 반응 → 마지막 상태를 읽히게 쓴다.
6. 시간표는 0초부터 요청 종료까지 이어진다. 한 비트의 주 카메라 이동은 하나를 기본으로 하며 시작 구도·경로·초점·끝을 연결한다. 고정 숏도 유효하다. 원샷에 숨은 컷을 넣지 않는다.
7. LIGHTING LOCK에 광원 방향·색·질감과 허용 변화, REF LOCK에 유지할 정체성과 허용 변화를 쓴다. 보존 지시가 의도한 움직임·발광·변신을 금지하지 않게 한다.
8. 오디오를 NO BGM/완전 무음/원본 소스만/무반주 보컬/음악 포함 중에서 선택한다. NO BGM은 허용 현장음·대사를 유지하고, 완전 무음은 호흡·룸톤도 추가하지 않는다. 원본에 음악이 있으면 원본 보존과 음악 제거를 동시에 약속하지 않는다.
9. 수정은 바뀐 층과 종속된 타임라인·초점·소리까지 재설계한다. 폐기된 지시를 제거한 전체 교체 프롬프트 하나를 반환한다. 관찰하지 않은 실패를 확정 진단하거나 수정 요청만으로 재생성을 실행하지 않는다.

## 출력

한국어 요청에는 한국어로 작성한다. 사용자가 원할 때 영어 버전을 제공하며 대사는 지정 언어·문구 그대로 유지한다. 설정 한 줄과 복사 가능한 전체 프롬프트 코드 블록을 준다. 내부 형식은 아래 8개 절을 사용하되 짧은 장면은 짧게 쓴다.

참조 → 피사체 → 배경 → 타임라인 → 카메라 → 스타일 → 오디오 → 제약 조건

마지막 물리 상태는 타임라인 끝에, 카메라 끝 구도는 카메라에 둔다. 각 절의 필수 정보가 있으면 장황한 금지 목록을 추가하지 않는다. JSON은 실제 API 요청이나 사용자가 원할 때만 사용한다. 문장의 타임코드는 연출 의도이며 프레임 정확도 보장이 아니다.

## 생성 요청을 받았을 때

프롬프트 작성은 영상 생성 허가가 아니다. 실제 생성 요청에만 연결 도구를 검색하고 모델 목록·스키마·입력 모드·비용을 확인한다. 연결이 없으면 완성 프롬프트를 전달하고 생성했다고 말하지 않는다. 현재 도구가 지원하지 않는 기능을 다른 서비스로 몰래 대체하지 않는다.

허가 범위 내에서 한 작업을 제출하고 반환된 식별자로 완료를 조회한다. 응답이 불명확하면 중복 제출 전에 상태를 확인한다. 제한된 재시도 후 인증·지속 실패·비용 초과 원인을 알린다. 자격증명은 출력하지 않는다. 성공 응답과 파일/링크 접근 여부를 확인하고 재생 검수 여부를 구분한다. 게시·타인 전송은 별도 요청이 있을 때만 수행한다.

## 자체 점검

실제 참조인가? 요청 길이와 모드가 지원되는가? 인물이 움직여야 할 때 구체적으로 움직이는가? 손·물체 접촉이 이어지는가? 카메라 경로와 컷 정책이 일치하는가? 음향 모드가 모순 없는가? 마지막 상태가 명확한가? 바뀐 요청의 이전 지시가 남아 있지 않은가?
